# Passport OS 屏幕区域与布局规范 v1.0（Codex 开发交接）

> 状态：设计规范 / 待真机验证。适用平台：FoloToy AI Passport，240 × 320 像素纵向屏幕，三枚实体按键。目标：在 ESP-IDF + LVGL 的 Passport OS 中实现稳定的系统栏、应用内容视口、全屏模式、按键导航和安全退出机制。

## 1. 目标与非目标

**目标**
- 所有第三方小程序共享统一的显示区域和坐标语义，应用不得覆盖 OS 保留区域（除授权的全屏模式）。
- OS 统一控制系统状态栏、底部操作提示、焦点导航、应用切换、异常恢复和全屏退出。
- 兼容声明式 UI 与 Lua/Canvas 游戏，开发者通过统一 API 获取实际可用视口。
- 优先复用 LVGL、显示 BSP 和现有按键驱动，低 RAM 占用、不使用全屏 RGB565 缓冲。

**非目标（v1）**：多窗口、分屏、横屏自动旋转、系统通知浮窗、通用 CSS、任意应用控制 LCD 驱动和背光硬件。

## 2. 显示模式与像素规范

物理屏幕：`width=240`、`height=320`，逻辑像素与物理像素在 v1 中 1:1 对应。坐标原点左上角，x 向右、y 向下。

| 参数 | 标准模式 `standard` | 全屏模式 `fullscreen` |
|---|---:|---:|
| 物理屏幕 | 240×320 | 240×320 |
| 状态栏 | `x=0, y=0, w=240, h=24` | 隐藏 |
| 应用视口 | `x=0, y=24, w=240, h=272` | `x=0, y=0, w=240, h=320` |
| 底部提示栏 | `x=0, y=296, w=240, h=24` | 隐藏 |
| 默认内容内边距 | 左右各 8 px（布局容器默认值，可改） | 0 px（应用自行控制） |
| 应用坐标原点 | 视口内 `(0,0)` 映射到屏幕 `(0,24)` | `(0,0)` 映射到屏幕 `(0,0)` |

**重要**：24px 和 272px 属于 v1 设计常量，须真机验证字体、中文文本高度和可读性后定稿；不应写死在第三方应用中。系统提供 `getViewport()` 查询值。左右 8px 内边距只是默认布局策略，**不**减少应用视口返回的宽度。

## 3. 系统栏职责

### 3.1 顶部状态栏（仅标准模式）
- 默认显示：应用名称（超长省略）、网络连接状态（Wi-Fi/蜂窝/离线）和电池图标/电量（有数据时）。
- 所有内容由 OS 产生；应用不得在状态栏创建 UI 对象。
- 更新由事件驱动，不能为了图标刷新而定期全屏重绘。
- 若 240px 空间不足：优先保留网络、电池；应用名称截断，必要时隐藏非关键状态。

### 3.2 底部导航提示栏（仅标准模式）
- OS 按当前焦点上下文显示 `↑↓ 选择 · OK 确认` 等操作提示。
- 应用可提供受限的提示意图（如 `up/down=scroll`, `ok=select`），OS 决定图案与布局；不允许自由注入任意渲染命令。
- 在内容空间受限或临时全屏媒体场景，可考虑未来版本动态隐藏；v1 保持固定 24px。

## 4. Fullscreen 的权限和退出规则

- 应用通过 Manifest 声明 `display.mode=fullscreen`，OS 审核和启动时应用模式；不允许直接修改 LVGL 根屏或系统窗口。
- 全屏仅影响可见系统栏，**不授予应用系统权限**。
- **强制退出永远有效**：建议默认长按 `OK` 约 2 秒弹出系统级退出/返回菜单。按键驱动需区分短按与长按，确保普通 OK 操作不会误触系统菜单。
- 系统级长按拦截优先于应用按键回调，应用不能禁用、吞掉或修改该行为。长按阈值最终须真机验证可用性。
- 应用崩溃、超时或脚本超预算时，OS 销毁会话，回到 Launcher，恢复系统栏和按键状态。
- 对连续按键等游戏操作，提供按下/释放/长按事件，但保留系统快捷键优先级。

## 5. App Manifest（拟议格式）

标准应用：

```json
{
  "format": "passport.app/1",
  "id": "com.example.weather",
  "display": { "mode": "standard", "orientation": "portrait" }
}
```

全屏游戏：

```json
{
  "format": "passport.app/1",
  "id": "com.example.tetris",
  "display": {
    "mode": "fullscreen",
    "orientation": "portrait",
    "design_width": 240,
    "design_height": 320
  }
}
```

- `mode` 必须为 `standard` 或 `fullscreen`；缺省为 `standard`。
- `orientation` v1 仅支持 `portrait`，其他值应返回清晰的兼容性错误，而非静默错误旋转。
- `design_width/height` 只表示开发者参考尺寸，不得覆盖实际 `viewport`；应用必须能够读取运行时的有效尺寸。
- 包格式、字段命名应与主项目已实施的 Manifest 保持兼容；如果实现不同，更新 SDK 和迁移文档，不要生成两套互相冲突的格式。

## 6. 对小程序开放的 Display API

设计为与 Lua、声明式 UI、未来 XS 无关的系统能力接口：

```text
passport.display.getViewport() -> {
  width: uint16,
  height: uint16,
  safeInsets: { left:uint8, top:uint8, right:uint8, bottom:uint8 },
  mode: "standard" | "fullscreen"
}
```

- 返回的是应用内容坐标系；标准模式返回 `{width:240,height:272}`，全屏返回 `{width:240,height:320}`；建议 `safeInsets` 默认都为 0，UI 布局的 8px padding 另作主题默认值，避免重复扣除。
- `display.requestMode(mode)`：v1 不向应用暴露动态切换；模式在启动时由 Manifest 确定。确有需求可在未来通过受限系统请求增加。
- `ui` 组件布局和 `graphics` Canvas 都只绘制到应用视口，并进行坐标裁切。超出视口的绘制不会污染系统栏。
- 应用 API 不能返回 LVGL 原始指针、物理帧缓冲指针、LCD SPI 句柄或系统 UI 对象。
- `getViewport()` 与 UI DPI/字体缩放未来可以扩展，但新增字段不得破坏旧应用。

Lua 示例（接口名称以 SDK 最终实现为准）：

```lua
function on_start()
  local viewport = passport.display.get_viewport()
  game_w, game_h = viewport.width, viewport.height
end
```

## 7. LVGL 实现指导

- Display Manager 独占主 LVGL 屏幕管理；创建 `SystemStatusBar`、`AppViewportHost`、`SystemNavBar` 三个容器（标准模式）；全屏仅显示 `AppViewportHost`。
- 应用 UI 的根对象只能挂载在 `AppViewportHost` 之下；禁止应用持有或遍历系统根对象。
- 视口容器应 `clip` 子对象；UI 层在受控任务中执行，网络/脚本回调通过队列提交更新。
- 所有 LVGL 对象操作必须遵循工程对应版本的线程安全与加锁规则，优先复用 BSP 已有锁。
- 帧缓冲采用局部刷新：`240×320×2 ≈ 150 KiB`，不得默认分配整屏 RGB565 缓冲；绘制缓冲按真机堆可用量选择。
- 全屏 Canvas 若需要重绘，优先脏矩形/局部无效化；简化小游戏可用 LVGL 绘图对象实现，不引入大型游戏引擎。
- 切换标准/全屏后严格检查对象树，避免旧栏、焦点、定时器泄漏。

## 8. 焦点与三键输入

- Input Manager 接收物理三键事件，并映射为稳定的应用事件（具体物理键名从 BSP 映射，不在协议里假设 GPIO）。
- 标准模式：默认 `UP/DOWN` 移动焦点或滚动、`OK` 激活；应用可声明语义并接收受控事件。
- 全屏模式：允许游戏自定义短按键动作；OS 始终优先处理长按退出。
- 长按、连按、消抖、焦点恢复由 OS 统一处理，不交给每个小程序分别实现。
- 进入/退出 App 后，焦点默认回到有效 UI 节点，不能出现按键焦点落在已销毁对象上的情况。

## 9. UI/资源布局建议

- 标准布局以 224px 推荐内容宽度为基础（240 - 8×2），组件可以按比例自适应，不得写死绝对屏幕位置。
- 图标优先使用系统 Icon Registry；标准界面小图标 A1/A4，应用彩色图标 I4，避免应用自行解析 SVG。
- 应用可使用文本、列表、按钮、对话框等系统组件；复杂游戏使用受限 Canvas。
- 对话框默认由 OS/Capability 层绘制为系统级覆盖层，确保权限弹窗始终高于应用且不可伪造；普通 UI 对话框仍在应用视口内。
- 文字与多语言：检查中文字体高度、裁切、换行、字号，保证 24px 系统栏易读；不要强制所有文本使用同一字号。

## 10. 生命周期与资源回收

启动应用：读取并验证 Manifest → 创建 App Session → 应用视口 → 标准栏/全屏状态 → 应用根 UI → 分派 Start 事件。

退出应用：阻止新事件 → 取消挂起能力与定时器 → 停止 Game Loop/动画/音频订阅 → 在 UI 任务释放应用对象 → 恢复系统栏 → 释放 App Session 的 UI/脚本内存。**退出不删除 App Package 或 Persistent App Data**。

应用崩溃：显示系统错误页面或返回 Launcher；全屏模式必须恢复系统导航能力。

## 11. 开发任务拆分（Codex）

- **D0 — 基线与版本识别**：核对当前官方 BSP、实际 LVGL 版本、LCD 方向、按键映射、显存与堆情况；建立资源测量记录。
- **D1 — Display Manager**：实现标准模式 24/272/24 布局、容器裁切、状态栏和导航栏。
- **D2 — Fullscreen**：实现 240×320 视口、系统栏隐藏和双击 OK 返回主页。
- **D3 — Manifest & SDK**：解析 `display.mode`；统一 Lua/声明式 App 视口 API 和坐标语义；补 SDK 文档。
- **D4 — 焦点/三键**：标准焦点导航、游戏模式输入、消抖、长按优先级。
- **D5 — 示例集成**：天气（标准）、WebSocket 聊天（标准）、俄罗斯方块（全屏）、声控飞行（全屏）。
- **D6 — 性能、压力与回归**：重复切换应用、局部刷新、文本溢出、异常退出、内存检查；形成验收报告。

不得只提交设计代码而不构建、不测试；没有真机则必须明确标注 `NOT RUN (hardware unavailable)`，不得虚构测试结果。

## 12. 验收清单

- [ ] 标准模式视口实测为 240×272，状态栏/导航栏各 24px，应用不能覆盖。
- [ ] 全屏模式视口实测为 240×320，状态栏/导航栏隐藏。
- [ ] 应用 `getViewport()` 返回与绘制实际一致的大小。
- [ ] 天气、聊天标准模式下中文文本、焦点、滚动正常。
- [ ] 俄罗斯方块、声控飞行全屏运行，双击 OK 能可靠返回主页。
- [ ] 全屏游戏超时/异常退出后状态栏与 Launcher 自动恢复。
- [ ] 200 次以上应用切换与销毁无持续增长的资源占用（按可用测试时间增加至 500 次）。
- [ ] LVGL 更新不会跨线程非法调用；无闪烁/系统栏污染/明显绘制错误。
- [ ] 峰值堆、最大连续堆、帧耗时和对象计数有测量报告。
- [ ] SDK、Manifest、模拟器、示例和主交接文档中的显示模式一致。
