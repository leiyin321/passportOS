# Passport OS 设计与实现审查

日期：2026-10-26。分支：`feature/passport-os`。设备基线为 OS 1.0.21、
小智 0.2.3。本次交付包含源码审查和经过测试的优化增量，不代表所有子系统
都已完成硬件验收。保留工程已有未提交修改，继续使用系统更新服务交付，
Flash 分区布局不变。

## 架构判断与审查范围

单前台 AppSession、签名 PAP 包、有界 Lua/声明式运行时、系统持有硬件服务、
应用包与私有数据分离、双槽 OTA，仍适合无 PSRAM 的 ESP32-C3，应继续保留。
应用服务语义和认证由 MiniApp 实现；OS 提供通用 HTTP/WSS、JSON、音频和显示原语。

审查了 `main/passport_main.c`、`os/core`、`os/package`、`os/runtime`，
以及网络、音频、显示、存储、时钟、设置、OTA 服务、BSP 集成、`protocol`、
`sdk/passport`、模拟器及相关回归测试。读取了固定版本 ESP-IDF 5.5.3 的 HTTP
实现以确认分块响应语义；没有声称完整独立审计了所有第三方 Lua/LVGL/codec 内部实现。

## 已实施方案

| 编号 | 优先级 | 问题与改进 | 证据/检查 |
| --- | --- | --- | --- |
| R01 | P0 | 所有网络操作固定分配 9,308 字节 job，含未使用的请求体、HTTP/WS 请求头。改成紧凑请求头、偏移索引、按实际大小分配 POST 请求体；增加目标平台 4 KiB 编译期限额及拒绝日志。 | ESP32 ELF：job 为 3,176 B，请求头为 1,064 B。测试覆盖往返、边界、重复、保留头和 CR/LF/NUL 注入；真实 worker 在单块最多 8 KiB 的分配器下测试。 |
| R02 | P0 | Lua 编译完成后仍持有源码，浪费内存。现在执行顶层代码/on_start 前释放；声明式文档解析后也释放。明确源码所有权被消费，再次启动前须重新加载包。 | 小智源码 13,744 B，另加终止符。模拟器断言启动成功后源码已释放，原有应用场景执行真实运行时。 |
| R03 | P1 | TLS 握手前预分配完整响应；把分块响应的长度 0 当成空响应。改为收到数据后增长缓冲，区分未知长度、解析完成、传输失败和超限，支持 POST 短写续传，POST 不跟随重定向，GET 下一跳前不消费/转交重定向响应体。 | HTTP 测试覆盖分块/EOF、恰好达到上限、空响应、超时、截断和 OTA 精确长度；保留读取超时及容量上限。 |
| R04 | P0 | 普通 RMS 模式不需要流式解码缓冲，却因其为 NULL 被错误初始化为 NO_MEM。按模式判断。 | 新宿主测试直接执行 `audio.c`，覆盖 RMS、Opus、回复播放、分配/任务/初始化失败和退出回收。 |
| R05 | P0 | 已有 Opus stream 时主循环仍调用 RMS 启动，模式冲突导致麦克风权限被撤销。按当前运行时音频模式调度。 | 固件编译和真实音频服务模式/停止测试通过，物理按住说话及 TTS 待设备验收。 |
| R06 | P1 | 主循环每条回调路径都携带 2 KiB WS 接收栈缓冲。拆成禁止内联的接收分发函数。 | 目标反汇编：主循环固定栈帧从 2,752 降到 1,168 B；不是最坏嵌套调用栈峰值。 |
| R07 | P1 | 闹钟仅在第 0 秒检查，主循环被网络/存储延迟后可能漏响。允许在目标分钟内触发，保留按天去重。 | 测试第 17 秒触发、同日不重复；阻塞超过整分钟仍属于调度器后续工作。 |
| R08 | P0 | JSON 递归解析后才检查限制；Lua 分配失败可能跳过 cJSON 清理。解析前预检深度/值数量，保护 Lua 转换/字符串创建，释放临时 C 内存后再传递 OOM，拒绝 NUL 键值。 | 真实运行时测试覆盖深层输入、重复/NUL 键、256 值边界和正常配网；运行时 26 项通过。 |
| R09 | P1 | 目录 Schema 缺少 audio.stream/device.identity；API 元数据残留旧视口与音频说明。同步实现与规范。 | 目录/Manifest 权限一致性测试及原有包/Schema 测试。 |
| R10 | P1 | CLI 未收到完成响应仍返回成功，ACK 后的 worker 日志被丢弃。增加有界 --observe/--verbose，超时/失败返回非零，拒绝换行/NUL 参数；实现文档中的 pin on/off。 | 模拟串口覆盖超时、失败、正常 ACK 和 ACK 后日志；固件编译覆盖 pin 解析。 |
| R11 | P1 | 发布直接覆盖正在服务的镜像、目录、清单文件。改为原子替换，OTA 清单最后提交；强制递增 build，已有版本镜像不可改写。 | 中断发布保留旧清单/镜像；拒绝倒退 build 和复用版本覆盖；签名验证通过。 |

## 资源证据

| 指标 | 优化前 | 优化后 | 测量类型 |
| --- | ---: | ---: | --- |
| 网络 job，ESP32-C3 布局 | 9,308 B | 3,176 B | 匹配 ELF 的 DWARF，减少 6,132 B/65.9%，不含另行分配的实际 POST 请求体 |
| job 请求头存储 | 4,112 B 键值数组 + 1,025 B WS 副本 | 1,064 B 共用存储 | 编译类型布局，不记录敏感内容 |
| 编译后保留小智源码 | 13,745 B | 0 B | 源码加终止符，在 on_start 前释放 |
| TLS 握手阶段预分配自定义 HTTP 响应 | 8,193 B | 0 B | 源码分配生命周期；后续响应仍受 limit+1 限制 |
| app_main 固定栈帧 | 2,752 B | 1,168 B | 目标反汇编，主任务栈仍为 8 KiB |
| 基线真机空闲堆/最大连续块 | 25,140 / 8,192 B | 等待 OTA 验收 | 1.0.21 小智等待网络时串口实测 |
| 基线主任务最少剩余栈 | 796 B | 等待 OTA 验收 | 真机栈高水位 |

旧版请求分配 9,308 字节，超过已观测到的 8,192 字节最大连续空闲块，因此即使
总空闲内存足够也可能无法分配，和持续等待的现象吻合。这不能证明修改后 DNS、
TLS、服务激活、WSS 和音频都能通过。不能把表中的节省值简单相加当成真机 RAM 峰值。

## 后续架构工作与验收门槛

以下明确属于后续工作，没有宣称已实现：

1. **P1：服务取消与退出确认。** `ps_net_cancel` 等待 16 秒，但固件读取可能阻塞
   60 秒，音频停止也可能超时。需要两阶段关闭：停止分发、请求取消、确认后才释放
   会话资源。覆盖 DNS/TLS/read/playback 中取消，以及旧 generation 回调隔离。
2. **P1：整机内存准入。** Lua、资源和传输目前分别限额，需要为 TLS + Opus + VM
   建立组合准入/预留及确定的内存不足错误。测量真实并行流式峰值，保留 TLS 验证。
   64 KiB Lua 是上限，不保证所有能力组合均能运行。
3. **P1：启动/升级故障矩阵。** 保留候选验证和回滚，补下载、槽位选择、确认阶段的
   断电测试及离线读取取消竞态验证。公开发布前分离固件签名与社区发布者信任/轮换策略。
4. **P2：拆分系统外壳。** 将约 2.4k 行主模块逐步拆分为 App Manager、设置控制器和
   开发者控制台，保留单事件所有者和 LVGL 锁。先用事件序列测试固定行为。本次仅隔离
   WS 分发，避免在修复网络时同步重写整个外壳。
5. **P2：性能与商店规模。** 测量回调 P50/P95 和 GC 成本后再替换每回调全量 GC；缓存
   已验证包元数据，避免列表版本查询反复验签和读取源码。超过 8 个商店条目前先增加分页；
   明确保留目前 8 个目录条目、12 个已安装应用上限。
6. **P2：补齐真实服务测试。** 模拟器替换了网络/音频。新增音频和 HTTP 测试执行真实服务代码；HTTP 使用 AddressSanitizer/UBSan，
   覆盖队列、POST 短写、分块尾部、重定向、容量/传输错误、分配失败和 OTA sink；
   500 次请求后跟踪分配全部回收。RTOS/socket/TLS/BSP 行为为测试桩，真实并发、TLS
   握手和整机资源漂移仍需目标设备测试。

  --verbose --observe 20 launch org.passport.xiaozhi

测试音频时在设备上处理已有麦克风授权提示。记录 HTTP 入队/完成或脱敏拒绝原因、激活结果、
WSS 握手、按住/松开和 TTS。启动前、连接后、音频中、`device home` 后分别记录 metrics；
重复启动退出，比较空闲堆/最大连续块、任务栈高水位、资源字节。不要将原始身份、认证头或
设备日志提交到文档。验证主循环延迟后的闹钟和系统中英文。这些仍是硬件待验收项，构建成功
不代表真机通过。
