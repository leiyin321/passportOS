# MiniApp 标准与开发工具审查报告

日期：2026-10-25 · 范围：Manifest/PAP、Capability、声明式 UI、SDK/CLI、示例、商店目录和宿主校验。

## 发现及改进

- 原 Manifest Schema 未覆盖源码清单和已编译 PAP2 资源记录的真实字段。现已替换为同时描述资源编译前后两种形态的 schema；SDK 也会校验必填类型/字段、未知顶层/限额字段、版本和 API 范围、权限、资源记录及 runtime/entry 对应关系。
- 原 `passport pack` 和 `passport validate` 会接受任意 UTF-8 声明式入口，包括运行时不支持的节点/操作、未声明图像资源和缺少权限的包。现新增 UI/1 有界预检，检查解析/资源限额、支持的节点和操作、绑定、定时器、数据请求、资源引用及所需权限。`navigate` 原本只改写状态键、不会实际导航，已从 SDK 和设备运行时中移除。
- 声明式 UI 缺少机器可读协议和开发者说明。现已新增 UI/1 schema 及双语规范，说明实际绘制限制和操作/数据行为。
- 设备支持多个发布者，但静态目录生成工具原先只接受一个公钥。`passport publish-index` 现支持重复传入 `--public`，逐包验证提供的发布者密钥，拒绝重复 App ID 和超过设备当前 8 项上限的目录。新增目录 schema，并说明目录自身没有签名；应用包签名和设备端发布者确认仍是信任依据。
- 示例 HTTP 服务原先默认监听全部网卡。现在默认绑定 `127.0.0.1`；需显式使用 `--host 0.0.0.0` 才开放局域网，文档说明该服务没有身份验证。
- MiniApp SDK/运行时/资源测试套件已集成到 `./tools/validate.sh --static`，纳入常规宿主门禁。

## 未完成项

- 设备 App Store 当前最多接受 8 个目录条目，尚无分页。生成的目录必须遵守此限制；扩展公开目录前应先实现分页并测量资源占用。
- `passport validate` 不会执行 Lua。开发者仍需跑模拟器/运行时行为测试，再做真机验收；包有效不代表应用行为或显示正确。
- 社区发布者审核、密钥撤销/轮换和目录所有权规则仍需确定；多公钥目录生成不会自动在设备上注册发布者。
- GitHub Pages 公开部署、公开仓库干净检出/可复现发布工作流仍推迟到 Passport OS 稳定并批准开源后实施。
- 小智实现已增加宿主模拟的配置请求、认证 WSS v1 握手、按住说话状态路径、有界 Opus API 和双语对话界面。目标服务激活、实际 Opus 帧/播放、资源使用和双语屏幕渲染仍需真机验收。小智握手与配置逻辑仍在应用代码中。详见[小智 AI MiniApp](../developer/xiaozhi-miniapp.zh_CN.md)。
