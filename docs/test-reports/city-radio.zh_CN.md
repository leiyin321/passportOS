# Native 城市电台验收检查点

应用 0.1.0、OS 1.0.51，ESP32-C3／8 MB／无 PSRAM。[操作与 API](../developer/city-radio.zh_CN.md)。日志和广播采样保存在忽略目录 `local/city-radio/`，应用不包含广播录音或凭据。

## 测试与限制

- Native 应用主机测试：PASS，覆盖旧系统扩展大小检查、离线／重试上限、暂停／继续、音量、搜索、菜单、十条去重历史、损坏存储、重启恢复、定时到期、风格、时钟及中英文。
- MP3 解析／解码：PASS，合成 16 kHz 正弦音，100 次独立解码器循环，分块长度 1–100 字节；覆盖 ID3／垃圾数据上限及输出拒绝。使用 AddressSanitizer／UndefinedBehaviorSanitizer。另在 macOS 解码九组真实流采样：平台 ID 339、270、274、4848、1270、1271、1133、1163、4237，各 16–21 帧。证明格式／解码有效，不证明节目名称或 C3 吞吐。
- OS 媒体服务主机测试：PASS，真实解码器配合模拟网络／BSP，完成 100 次启动／播放／停止／关闭；覆盖重叠启动及采集所有者拒绝、PCM 失败和 EOF 回收。macOS `leaks --atExit` 检查结果为 **0 处泄漏／0 字节泄漏**。这是主机内存回收，不是设备堆恢复测量。
- 网络工作任务：PASS，既有 HTTP／OTA／WS 回归以及播放权限、无长度 EOF 流、白名单内相对重定向、未授权目标拒绝、输出失败及错误响应。保留 TLS／DNS 策略。流任务复制域名／URL，仅保留 OS 自有回调及上下文。
- 字体测试：PASS，覆盖城市电台全部非 ASCII 界面文字，共享字体补入“圳”字，保留此前字形集合。实际屏幕显示待验收。
- 台源可用性存在波动：首轮取得 HTTP 200／audio-mpeg，后续并发探测中部分超时。界面限制重试次数，允许手动重试或换台。持续可用性及实际节目名称尚未核实。

## 卡顿定位与实机跟进

用户通过 USB-C 连接开发板并授权直接操作。使用 `/dev/cu.usbmodem101`、设置中的 OTA 及既有城市电台 0.1.0 应用包。不进行 USB Flash 写入、擦除、清除配对或删除应用数据，应用 API／包保持不变。

- 修复前：上海新闻台约十六秒只产出九十帧 MP3（44.1 kHz 时约 2.35 秒音频），伴随 TLS `-0x7100` 读取错误。网络、标量浮点解码与 PCM 写入共用一个任务，解码／读取延迟会耗尽短 DMA 缓冲；配置的 8 KiB TLS 记录上限也无法接收任意标准 16 KiB 记录。
- OS 1.0.52：整数解码、独立播放任务、4 KiB 压缩队列及 16 KiB TLS 输入。用户确认明显改善，基本连续，但偶有细微卡顿。实测 1,703 帧，音频 44,485 毫秒／经过 45,177 毫秒；平均解码 5,562 微秒、最大 10,248 微秒；四次断流，最大供音间隔 316,003 微秒。
- OS 1.0.53 的 12 KiB 队列实验版不作为最终交付：动态 TLS RX 分配失败（15,772 字节，随后读取也失败）。原始日志留在本机，仅扩容不能解决堆碎片。
- OS 1.0.54：8 KiB 队列，媒体请求单独采用 `HTTP_TLS_DYN_BUF_RX_STATIC`，握手后、解码器延迟分配前保留完整接收记录。连续约九十二秒解出 3,523 帧：音频 92,027 毫秒／经过 92,047 毫秒；平均解码 5,465 微秒、最大 10,557 微秒；**零断流**，最大供音间隔 11,314 微秒；该轮没有 TLS／分配失败。设备空闲堆最低 6,392 字节，播放／网络栈余量 3,304／1,784 字节；退出恢复 107,860 字节，Native 池占用归零。随后快速重连测试仍有暂时连接超时及部分断流，未完成十轮成功播放。

OS 1.0.55 在媒体网络任务期间额外请求 `WIFI_PS_NONE`，完成／失败／取消后恢复此前模式。开发板日志声明 `bi=102400 us`、`li=3`（307.2 毫秒），实际唤醒还受 DTIM 和省电策略影响，支持将休眠列为待排除抖动因素，但不能证明每次网络超时都由省电造成。预缓冲改为完整十六块／8 KiB（64 kbit/s 时约 1.024 秒）。空队列等待期间停止不再计入断流。主机测试检查固定 RX 仅用于媒体、普通 HTTP 策略不变，以及 Wi-Fi 模式申请／恢复成对执行。

## 2026-10-30 续测：OS 1.0.58 与短读取修正

前面的记录是历史检查点，不代表当前验收。OS 1.0.56 的固定 32 KiB 试验出现 Wi-Fi 接收分配失败，1.0.57 缩小缓冲后仍断流。1.0.58 增加仅输出 BSP 初始化、4 KiB 播放栈、1,536 字节帧组装及解码器/DAC 初始化后的自适应扩容。

- 1.0.58 标准源：3,441 帧，音频 89,885 ms / 实际 89,913 ms，断流 0 次，最长供音间隔 11,898 us，平均解码 4,932 us。实际 59 块；采样空闲堆最低 9,744 字节，全局最低 7,676 字节；播放/网络栈余量 1,740/2,440 字节。
- 1.0.58 + 应用 0.1.2 流畅源：3,117 帧，音频 81,422 ms / 实际 88,351 ms，断流 1 次、间隔 6,918,716 us。实际 63 块；采样最低 7,460 字节，全局最低 3,332 字节；退出空闲堆 107,584 字节、Native 池为零。此轮不能判定播放连续。
- 独立 Mac 接收测试：相同北京音乐 `/24k.mp3`，48.671 秒收到 258,048 字节，反复出现 5.23–5.64 秒接收间隔；源实测 32 kbit/s。这证明突发交付不只发生在设备上，不能据此解释每次局部卡顿。

OS 1.0.59 将短读取拼满 512 字节再排队，EOF 前提交尾块。此前每次短读取都独占块，块数不代表有效字节容量。新增逐字节分片及 EOF 尾部回归测试。完整构建及实机长测结果将在完成后追加。原始日志保留在忽略目录 `local/city-radio/stutter/`。未擦除芯片、清除配对或通过 USB 刷固件。
