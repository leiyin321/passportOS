## 资源记录

ESP32-C3 OTA 应用分区大小为 2,621,440 字节。固件 1.0.20 使用 2,280,576 字节，剩余 340,864 字节（13.0%）；首次刷机合并镜像为 2,411,648 字节。ELF 段统计的链接期 DRAM 区域占用为 180,748 字节（102,400 字节保留/占位区域 + 13,716 字节 data + 64,632 字节 BSS）。这是静态链接占用，不包含运行时堆峰值；Lua 峰值是宿主模拟器测量值，并非 ESP32 RAM 数据。

固件产物目录：`build/firmware/724c75da75838d2b481aad39c0437293a55bef827a169814151044c49fde31c6/`。完整镜像 SHA-256：`724c75da75838d2b481aad39c0437293a55bef827a169814151044c49fde31c6`。

音频路径使用容量为 3 的 Opus 收发队列，采集 16 kHz 单声道、每帧 60 ms。音频 worker 负责释放 codec context 和解码 PCM 缓冲区；MiniApp 退出时停止并删除 worker，同时删除队列和信号量。运行日志会报告任务栈高水位、codec 关闭前后的空闲堆、最大连续空闲块以及全部清理后的空闲堆（`AUDIO reclaimed`）。这些只是日志测量点，不是实机测量结果。

## 网络 worker 忙碌恢复 0.2.3

用户遇到的“请先在设置中连接 Wi-Fi”也可能出现在 `ps_net_request()` 因 OS 共用 HTTP worker 正忙而拒绝提交时；应用之前把所有即时 `false` 都误判为 Wi-Fi 断开。0.2.3 现在显示本地化的网络等待提示，并在 1 秒后重试。HTTP `-1`、408、429 和 5xx 临时错误会在 3 秒后重试；永久 HTTP 错误仍会显示，避免无限重试。

## TLS 分配失败：OS 1.0.24 / 小智 0.2.4（2026-10-26）

通过 USB 日志在修复前的设备上复现：尚未收到 HTTP 响应，出现 `stage=open`、`ESP_ERR_HTTP_CONNECT`、证书验签 `0x4290`，随后握手 `-0x3000`。本机 ESP-IDF 5.5.3 头文件表明 `0x4290` 是 RSA 公钥运算失败（`0x4280`）与 MPI 内存分配失败（`0x0010`）的组合。Wi-Fi 网络策略已通过。这证明验签过程分配内存失败，并不证明服务器证书无效或 Wi-Fi 离线。启动以来最低空闲堆为 40 字节；应用退出后恢复到 77,740 字节。这些是修复前的数据，不是新版测量。

## WSS Host 路由失败：OS 1.0.26

在 1.0.25 设备上，新日志出现 `Certificate validated`，本次握手没有再发生之前的 TLS 分配失败。握手前空闲堆 31,996 字节、最大块 12,288、启动以来最低堆 9,852、Lua 31,917。随后 WebSocket 升级返回 HTTP 502，缺少 Sec-WebSocket-Accept。在 Mac 上对 `/xiaozhi/v1/` 使用相同升级参数且不带设备凭据做真实 HTTPS 对照：Host 为 `api.tenclass.net` 时返回 101；Host 为解析后的 IP 加端口时返回 502。由此将本次失败定位到 Host 路由，而不是 hello JSON。

## Opus 协商及音频任务栈：0.2.6 / OS 1.0.27

应用错误地要求服务器下行采样率必须等于麦克风/本机输出的 16 kHz。Opus 支持将受支持采样率的码流直接解码为选定输出采样率（[解码器 API](https://www.opus-codec.org/docs/opus_api-1.6/group__opus__decoder.html)）。0.2.6 接受 8/12/16/24/48 kHz 单声道 Opus、声明帧长不超过 60 ms，继续拒绝非法格式、声道、采样率及过长帧；录音延后到下一次 tick 启动。OS 已将 Opus 解码及 I2S 输出设置为 16 kHz，无需新增重采样器或专用 provider。未捕获服务器实际采样率，不能将 24 kHz 写成设备实测值。

测试：31 项运行时测试通过，包含八组有效/无效 hello 参数。使用真实主机 libopus，将 60 ms 测试音分别按 8/12/16/24/48 kHz 编码，再以 16 kHz 解码，五组均准确输出 960 个采样点。这验证主机编解码行为，不等于验证 ESP 编解码二进制。

设备越过参数协商后暴露栈保护异常。使用匹配的 1.0.26 ELF（`dc86f14af0124738e46028dbc6e897bc420ee4de4e4aff046e720bd1a5b3c2c4`）设置硬件断点，确认故障线程为 `passport_audio`；capture 原生栈帧占 4,752 字节，而任务栈仅 6,144 字节。后续 TCB 检查仍显示旧约 6 KiB 栈，因此寄存器修改实验不能作为新栈配置的验收证据。OS 1.0.27 仅将该任务栈提高到 10,240 字节，音频运行时额外占用 4,096 字节堆。新版栈余量、编解码堆需求、完整语音链路及退出回收仍需 OTA 后验证。未通过 USB 刷固件；已关闭调试器并复位恢复正常执行。
