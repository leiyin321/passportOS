# Native ELF applications

Passport OS 1.0.34 includes a trusted ESP32-C3 Native Runtime alongside Lua and declarative apps. A Native App is installed as an ordinary signed `.pap`, appears in the existing App Library, runs without restarting the OS, and returns to Launcher on exit. It is not an arbitrary ESP-IDF firmware image or a process sandbox.

## Build, sign and run

Activate the ESP-IDF 5.5.3 environment. The firmware and app use the same RISC-V toolchain (GCC 14.2.0, `rv32imc_zicsr_zifencei`, ILP32 soft-float).

```sh
PYTHONPATH=sdk python -m passport init /tmp/native-demo \
  --id org.example.native-demo --runtime native-elf
PYTHONPATH=sdk python -m passport native build /tmp/native-demo
PYTHONPATH=sdk python -m passport native inspect /tmp/native-demo/app.app.elf
PYTHONPATH=sdk python -m passport pack /tmp/native-demo \
  --key /path/to/os-publisher-private.pem --public sdk/publisher-public.pem \
  -o /tmp/native-demo.pap
PYTHONPATH=sdk python -m passport validate /tmp/native-demo.pap --public sdk/publisher-public.pem
PYTHONPATH=sdk python -m passport install /tmp/native-demo.pap \
  --public sdk/publisher-public.pem --port /dev/cu.usbmodem1101
PYTHONPATH=sdk python -m passport device launch org.example.native-demo --port /dev/cu.usbmodem1101
PYTHONPATH=sdk python -m passport device view --port /dev/cu.usbmodem1101
PYTHONPATH=sdk python -m passport device home --port /dev/cu.usbmodem1101
PYTHONPATH=sdk python -m passport device metrics --port /dev/cu.usbmodem1101
```

Use the actual device port. The example is at [`examples/native_hello`](../../examples/native_hello/main.c). `native build` compiles C translation units plus small freestanding compiler support; it does not link the BSP, LVGL or ESP-IDF into each app. Unresolved imports, unsupported relocations, invalid entry/segments and over-budget images fail preflight. Compiler errors are reported before packaging.

**Publisher policy:** Native v1 accepts only the built-in OS publisher. Trusting an additional publisher for Lua does not authorize Native machine code. `trusted:true` is a declaration, not self-authorization. Developers submit source/ELF for the OS publisher's review/signing; signing with another key can validate locally but is rejected by this OS. Never distribute private signing keys.

## Manifest and package

```json
{
  "format":"passport.app/1",
  "id":"org.example.native-demo",
  "name":"Native demo",
  "version":"0.1.0",
  "runtime":"native-elf",
  "entry":"app.app.elf",
  "target":"esp32c3",
  "abi":1,
  "trusted":true,
  "min_os_api":1,
  "data_schema":1,
  "permissions":["ui","graphics","input","timer"],
  "limits":{"native_exec_kib":16,"fps":10,"persistent_kib":1},
  "display":{"mode":"standard","orientation":"portrait","navigation":"buttons"}
}
```

Native entries contain binary bytes, including NUL, under the existing PAP1/PAP2 length/hash/signature envelope. Lua/declarative UTF-8 and code limits remain unchanged. `publisher_key_id` and `sha256` are generated by `pack`. Native v1 has a 32 KiB file limit and a maximum 16 KiB PT_LOAD span including metadata/padding/BSS; `native_exec_kib` may request less. `script_heap_kib` is not used for Native and must not be supplied. The generic `persistent_kib` field remains required by the package contract, but v1 has no Native private-storage API.

Only `ui`, `graphics`, `input`, and `timer` permissions are available through this ABI. Storage/network/audio/device-driver APIs are not exported in Native v1. Existing Lua capabilities remain available to Lua apps. Packages still use existing cache/registry/data ownership and the current App Store transport; firmware and apps remain separately updated.

## C ABI v1

The normative header is [`passport_native.h`](../../sdk/native/include/passport_native.h); the machine-readable summary is [`abi-v1.json`](../../sdk/native/abi-v1.json).

```c
int passport_app_entry(const passport_native_host_v1 *host,
                       passport_native_app_v1 *app);
```

Check `host->abi` and `host->size`. Fill `app->abi`, `app->size`, optional `event`/`stop` function pointers and return 0, or return a negative failure. OS checks callback version/size and that callbacks reside in loaded executable segments. Entry and callbacks are synchronous on the foreground context and must return promptly; an infinite loop can still crash/reset the OS. Native code has no Lua instruction hook or preemption sandbox.

| Host method | Contract |
|---|---|
| `text(utf8,color)` | Copy a NUL-terminated UTF-8 string shorter than 512 bytes into the managed view; RGB24 color; requires `ui` |
| `clear(background)` | Reset managed draw/image/text commands and fill the app viewport; requires `graphics` |
| `rect(x,y,w,h,color)` | Nonnegative coordinates, positive dimensions, RGB24; clips to viewport, at most 192 commands; requires `graphics` |
| `millis()` | Monotonic 32-bit milliseconds, wraps naturally; returns 0 without `timer` |
| `language()` | Read-only system language (`en` or `zh-CN`) |
| `display_mode()` | Read-only `light` or `dark`; app chooses its own palette |

Draw calls return 0 on success or -1 for invalid bounds/quota/permission. They update the managed view and never expose an LVGL pointer; the existing OS renderer owns LVGL synchronization. Standard 240x272 and fullscreen 240x320 contracts remain the same as Lua.

Events: press=1, release=2, short=3, double=4, long=5, tick=6. Button values: up=0, down=1, OK=2; tick value is elapsed milliseconds. Existing OS navigation reserves double OK for returning to Launcher. UP/DOWN do not generate double-click gestures. `stop` runs before code is cleared; no callbacks are dispatched after unload.

## Ownership, limits and security

A statically reserved 16 KiB pool is the app's code/data/BSS storage. It remains reserved while Lua runs; after Native exit its contents are cleared and reusable, not returned to ordinary heap. Generic EXEC heap remains zero intentionally. Memory protection and locking remain enabled; only the bounded pool is RWX. This is not dynamic W^X and does not isolate Native code from writable OS data.

No app-created RTOS tasks, interrupts, retained asynchronous callbacks, raw Flash/drivers, or OS-wide reinitialization are supported. Global variables and bounded stack scratch are supported; no OS heap allocator is exported. The SDK supplies module-local `memcpy`/`memset`/`memmove`/`memcmp` for compiler-generated operations. All native code is trusted and shares OS privileges; the function table is an API boundary, not a security boundary.

The OS unloads a single foreground image only after synchronous entry/events/stop return. The same AppManager session cleanup is used for Lua and Native. Removing code (`offload`) keeps private data; complete removal uses the existing explicit `remove` confirmation.

## Validation and troubleshooting

```sh
PYTHONPATH=sdk python -m passport device cycle org.example.native-demo 1000 \
  --timeout 300 --port /dev/cu.usbmodem1101 --verbose
```

`metrics` reports pool capacity/used/peak; `protection=0` in the current diagnostic line means verification returned `ESP_OK`, not that protection is disabled. `view` reports the runtime's text/error and Lua allocation. Native startup failure emits `PASSPORT launch FAIL`; the CLI reports failure and `view` provides the reason. A manifest ABI mismatch fails installation; a callback ABI mismatch unloads safely before accepting events.

For a malformed ELF, inspect ISA, entry, PT_LOAD bounds, relative relocations and undefined symbols. Native v1 requires little-endian ELF32 RISC-V ET_DYN with a zero-based load layout, no imports/TLS/constructors and only `R_RISCV_RELATIVE`. Check the declared executable budget and root-publisher signature before blaming networking or the generic EXEC heap.

## ABI 2 services (OS 1.0.35+)

ABI 1 remains compatible. ABI 2 adds generic HTTPS, WebSocket, JSON field access, device identity, private storage and Opus audio. See [ABI 2](native-services.md). Set manifest `abi:2`; OS 1.0.34 cannot run this profile and must be upgraded first.
